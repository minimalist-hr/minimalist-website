# Backend architecture (Worker)

The only server code is one Cloudflare Worker in `src/worker/`. It is stateless and stores
nothing.

## Files

| File                        | Responsibility                                                                                            |
| :-------------------------- | :-------------------------------------------------------------------------------------------------------- |
| `index.ts`                  | Entry (`main` in `wrangler.jsonc`). Routes `/api/contact` to the handler; everything else to `env.ASSETS` |
| `contact.ts`                | `handleContact`: the request pipeline below                                                               |
| `validation.ts`             | `parseInquiry`: authoritative server-side validation                                                      |
| `turnstile.ts`              | `verifyTurnstile`: calls Cloudflare siteverify                                                            |
| `compose.ts`                | The notification email to the studio (always English)                                                     |
| `autoreply.ts`              | The confirmation email to the sender (their language)                                                     |
| `mail/types.ts`             | `OutgoingMail` and `Mailer`: the provider seam                                                            |
| `mail/index.ts`             | `createMailer(env)`: picks the implementation from `MAIL_PROVIDER`                                        |
| `mail/resend.ts`            | Resend REST implementation                                                                                |
| `mail/console.ts`           | Local implementation that logs metadata only                                                              |
| `mail/layout.ts`            | Shared HTML email shell in the brand palette; `escapeHtml`                                                |
| `env.ts`                    | `WorkerEnv`: generated `Env` plus the optional secrets                                                    |
| `worker-configuration.d.ts` | Generated by `pnpm run types:worker`. Don't edit                                                          |
| `tsconfig.json`             | Workers runtime types; checked separately by `pnpm run check`                                             |

The Worker also imports from the site: `src/lib/inquiry.ts` (the contract), `src/i18n/*`
(locales, routes, UI strings for the auto-reply) and `src/site.config.ts`. Those files must stay
free of browser, Astro and Workers APIs.

## How requests reach the Worker

Cloudflare serves any request that matches a file in `dist/` directly, without running the
Worker. Only requests with no matching file reach it:

```ts
// src/worker/index.ts
if (pathname === '/api/contact' || pathname === '/api/contact/') return handleContact(request, env);
return env.ASSETS.fetch(request); // not_found_handling serves the nearest 404.html
```

## The contact pipeline

`handleContact` runs these steps in order and stops at the first failure.

| #   | Step                                                  | On failure                                         |
| :-- | :---------------------------------------------------- | :------------------------------------------------- |
| 1   | Method must be `POST`                                 | `405`, `Allow: POST`                               |
| 2   | `Origin`, if present, must equal the request's origin | `403`                                              |
| 3   | `Content-Length` ≤ 64 KiB                             | `413`                                              |
| 4   | Body parses as form data                              | `400`                                              |
| 5   | Honeypot `website` empty                              | Pretend success (`200 { ok: true }`), send nothing |
| 6   | `parseInquiry` passes                                 | `400 { ok: false, error: 'invalid', fields }`      |
| 7   | `TURNSTILE_SECRET_KEY` is set (fail closed)           | `503 { error: 'unavailable' }`, logged             |
| 8   | Turnstile token verifies                              | `403 { error: 'verification' }`                    |
| 9   | Notification sent to `CONTACT_TO`                     | `502 { error: 'send' }`, error code logged         |
| 10  | Auto-reply sent to the inquirer                       | Logged only; the response is still success         |
| 11  | Done                                                  | `200 { ok: true }`                                 |

Steps 1–4 return plain text. From step 5 on, the response depends on the `Accept` header:

- `Accept: application/json` (the JavaScript submit) gets JSON matching `InquiryResponse`.
- Anything else (a plain form post) gets a `303` redirect to the contact page in the form's
  language with `?status=sent|invalid|verification|send|unavailable`.

## Validation rules

From `src/lib/inquiry.ts`, applied by `validation.ts`:

| Field             | Rule                                                                                        |
| :---------------- | :------------------------------------------------------------------------------------------ |
| `name`            | Required, ≤ 120 chars, line breaks collapsed                                                |
| `email`           | Required, matches `^[^\s@]+@[^\s@]+\.[^\s@]+$`, ≤ 200 chars                                 |
| `company`, `role` | Optional, ≤ 120 chars, line breaks collapsed                                                |
| `brief`           | Required, ≤ 5,000 chars                                                                     |
| `consent`         | Must equal `yes`                                                                            |
| `timeline`        | Optional; `asap`, `1-3m`, `3-6m`, `exploring`; anything else is dropped                     |
| `budget`          | Optional; `lt500`, `500-2k`, `2k-5k`, `5k-15k`, `gt15k`, `unsure`; anything else is dropped |
| `locale`          | `en` or `hr`; defaults to `en`                                                              |

All values are trimmed. Single-line fields have line breaks removed because they end up in the
email subject.

## Email

**Notification** (`compose.ts`): to `CONTACT_TO`, from "Minimalist website" `<CONTACT_FROM>`,
`Reply-To` the inquirer, subject `Inquiry: <name>[, <company>]`. Plain text plus HTML with the
details table, the brief, a "Reply to <first name>" button and a footer noting the time
(Europe/Zagreb) and that the privacy policy was accepted. Always English.

**Auto-reply** (`autoreply.ts`): to the inquirer, from "Minimalist" `<CONTACT_FROM>`,
`Reply-To` `CONTACT_TO`, header `Auto-Submitted: auto-replied` (RFC 3834) so out-of-office
replies don't answer it. Its text comes from `email.*` keys in `src/i18n/ui.ts`. **It repeats
nothing from the form, not even the name**: anyone can type any address into the form, so a
false submission can only ever send this fixed text.

**Layout** (`mail/layout.ts`): table layout with inline styles, light by default (Gmail and
Outlook ignore `prefers-color-scheme`), dark in clients that support it (Apple Mail, iCloud).
Brand colours are repeated here because email clients can't use CSS variables reliably. Every
value from the form goes through `escapeHtml`.

## The Mailer seam

```ts
interface Mailer {
  send(mail: OutgoingMail): Promise<void>; // resolves when accepted, rejects otherwise
}
```

`createMailer(env)` switches on `MAIL_PROVIDER`:

- `resend`: needs `RESEND_API_KEY`; posts to `https://api.resend.com/emails`. Sends a
  `User-Agent` (Resend rejects requests without one). On failure throws an error whose `code`
  is `resend_<status>_<error name>`; Resend's `message` is dropped because it can contain addresses.
- `console`: logs recipient, sender and lengths, never content.

To add a provider, see [Change the email provider](/Guides/Change-the-Email-Provider).

## Configuration

| Name                   | Kind                   | Value                                             |
| :--------------------- | :--------------------- | :------------------------------------------------ |
| `ASSETS`               | Binding                | Static assets from `dist/`                        |
| `CONTACT_TO`           | Var (`wrangler.jsonc`) | `hello@minimalist.hr`                             |
| `CONTACT_FROM`         | Var                    | `form@minimalist.hr`                              |
| `MAIL_PROVIDER`        | Var                    | `resend` (overridden to `console` in `.dev.vars`) |
| `TURNSTILE_SECRET_KEY` | Secret                 | Cloudflare dashboard; test key in `.dev.vars`     |
| `RESEND_API_KEY`       | Secret                 | Cloudflare dashboard; optional locally            |

Secrets are typed optional in `env.ts` so previews and local runs work without them; the
handler fails closed where it matters.

## Logging

Workers observability is on, so logs appear in the Cloudflare dashboard. The Worker logs only:

- `[contact] TURNSTILE_SECRET_KEY is not set`
- `[contact] send failed: <code>` / `[contact] auto-reply failed: <code>`
- `[mail:console] would send to … (n char subject, n char body, n char HTML)` (local only)

Never log names, addresses, briefs or provider messages.

## Not here

No database, KV, queues, cron triggers, sessions or rate limiting beyond Turnstile. If any of
these become necessary, record the decision first.
